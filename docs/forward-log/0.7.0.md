# Yumlog 0.7.0 forward log

Status: planned. These specs collect work deferred from 0.6.0. Each item lists the goal, scope, acceptance checks, and open decisions. Items marked **needs decision** wait on dayour.

## 1. a2swe evaluation integration

- **Goal:** run a2swe evaluation passes over Yumlog Studio sessions (MDKG timelines, runbooks, AgentCards) and keep the scores beside the session.
- **Scope:** a `Studio > Insights` action that exports a session as an a2swe eval bundle (MDKG, runbook JSON, card, hashes) and imports a scored result back as a `evaluation` artifact. No a2swe code is vendored into Yumlog; the boundary is the bundle schema.
- **Acceptance:** a round-trip Pester test with a fixture bundle; a self-test check that imported scores keep their source hashes; Studio smoke covers the new action.
- **Open:** bundle schema owner (a2swe or Yumlog) and the versioning policy.

## 2. LayeredCards briefing kit

- **Goal:** build a briefing (cover, sections, and evidence cards) from a set of Paperboy video cards and WidgetStudio widgets.
- **Scope:** a `briefing.json` manifest (schema 1.0) that lists cards in layers, plus a preview renderer and a ZIP package that reuse WidgetPackageExporter. The kit lives in WidgetStudio.
- **Acceptance:** schema and sample in `apps/Yumlog.WidgetStudio`; self-test checks for validation, ordering, missing-card diagnostics, and package contents; the preview HTML renders with no network access.

## 3. Kokoro TTS model pack

- **Goal:** offer Kokoro as a local narration voice next to Windows voices in `Studio > Voices`.
- **Scope:** a model-pack format (`model-pack.json` with name, version, license, file list, and SHA-256 hashes) installed under `%LOCALAPPDATA%\DarbotLabs\Yumlog\models\kokoro\<version>`. Downloading is explicit and user-initiated, and the license is shown and never auto-accepted. Synthesis runs out of process and is tracked by `ChildProcesses`.
- **Acceptance:** an install, verify, and remove test against a stub pack; the Voices list shows Kokoro only when the pack verifies; narration output is decoded and hashed in the Agent Voices test.
- **Needs decision:** whether to host the pack as a GitHub release asset or fetch it from upstream, and the license review.

## 4. Whisper model as a release asset

- **Goal:** stop relying on a hand-copied `.tools/whisper` folder (about 162 MB, ignored by git).
- **Scope:** publish `whisper-<model>-<version>.zip` with a SHA-256 manifest as a separate release asset. `launchers/Install-YumlogVoiceTools.ps1` downloads it from the release, verifies it, and installs per user. The main Yumlog zip does not grow.
- **Acceptance:** the installer refuses a hash mismatch; Test-YumlogStudio passes on a clean machine after the voice-tools install; the release notes list the asset hashes.
- **Open:** which model (base.en or larger) and whether to include runtime binaries.

## 5. Yumlog codec replacing FFmpeg

- **Goal:** move from the 0.6.0 FFmpeg default to the in-process Yumlog HEVC path (NVENC or x265 with the MDKG mux) once it reaches parity.
- **Scope:** parity checks for record, clip, frame, scenes, wave, and spectrogram; a staged rollout with `record.backend` defaulting to `ffmpeg` until every parity check passes on the fleet, then a switch to `auto`; FFmpeg stays as the fallback.
- **Acceptance:** a parity matrix in CI (synthetic fixture) plus a fleet run on SMAX, antonstudio, HP11D, and the Dev Boxes; no regression in the Studio smoke harness.
- **Needs decision:** the go/no-go to flip the default.

## 6. Media-path normalization follow-ups

- **Goal:** make every card and manifest producer write portable paths.
- **Scope:** Studio exports write `media.path` relative to the card when the media sits beside it, and absolute otherwise. Harvest and bundle readers use one shared resolver (port `Resolve-PaperboyMediaPath` to .NET). Forward slashes, UNC paths, and drive changes are covered.
- **Acceptance:** the existing Pester fixtures plus .NET unit checks in the native self-test; a migration note for 0.5.x cards.

## 7. Dependabot alert #1

- **Goal:** clear the moderate alert on `main` (https://github.com/darbotlabs/Yumlog/security/dependabot/1).
- **Scope:** identify the package and path (the NPU emulator Rust or npm lockfiles are the likely source), then bump to a patched version with no other drift.
- **Acceptance:** the alert closes automatically; cargo check/test and the gate pass.

## 8. Copilot CLI PATH order (poweragent)

- **Problem:** `C:\ProgramData\global-npm` (machine PATH) holds a stale `copilot` (0.0.419) that shadows the WinGet copy in `%LOCALAPPDATA%\Microsoft\WinGet\Links` (user PATH). Windows puts the machine PATH ahead of the user PATH, so a user-only change cannot fix the order.
- **Options:** (a) with admin, remove or update the global-npm `@github/copilot` package or move WinGet Links ahead in the machine PATH; (b) without admin, add a `copilot` function to the user's PowerShell profile that calls the WinGet copy.
- **Needs decision:** whether to take option (a) or (b).
